Workflow Kit Architecture

apra-agent-kit — autonomous AI agent server built on Apra Fleet

Core Components

HTTP Layer The front door. Accepts task requests, serves the MCP tool endpoint, and hosts the chat UI. Swappable between Express (local/Docker), raw HTTP, or Azure Functions.
Job Queue Handles async tasks. When you fire-and-forget a task, it gets queued here and a worker picks it up. SQLite-backed locally, Azure Durable Functions in the cloud. Jobs go through: queued → processing → completed/failed.
MCP Server Exposes 15 tools as an MCP catalog so an external AI (like Claude Code) can call them directly, without the agent doing its own planning.
Strategy Engine The brain. Two modes: ReAct (simple loop — ask LLM what to do, do it, repeat) and Plan-Execute (doer makes a plan, reviewer approves, steps run one by one, replan on failure).
Budgets & Guardrails Safety rails around the strategy loop. Caps on iterations (25), cost ($5), tokens (500K), and time (10 min). Per-tool allow/deny policies and filesystem sandboxing.
Worker Pool Manages Claude Code instances. Three tiers: 4 pre-provisioned pairs grabbed instantly, up to 10 ephemeral overflow pairs, then a wait queue (max 20). Each pair has a doer and a reviewer.
Apra Fleet The foundation. Runs as a child process over stdio. Manages member workspaces, OAuth credentials, and spawns Claude Code CLI instances for each worker.
Notifications Pushes job progress out in real time. SSE stream for browser clients, webhook POST with retry for server-to-server callbacks.
Python Tools 15 tools (weather, currency, geocode, Wikipedia, etc.) — all plain Python using only stdlib, executed on Fleet member machines via executeCommand.
